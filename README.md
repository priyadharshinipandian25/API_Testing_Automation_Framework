# API Testing & Automation Framework

**Portfolio project:** REST API functional testing using Postman, Python, Requests and Pytest.

## 1. Project overview

This repository contains:
- A small demo REST API (FastAPI) that acts as the system under test.
- A Postman collection for manual and collection-based API checks.
- Python + Pytest automation tests.
- Positive, negative, CRUD and authentication scenarios.
- HTML test report generation.

The demo API is intentionally local and uses in-memory data. It is for learning and portfolio demonstration only, not production use.

## 2. Architecture

Tester / Postman or Pytest -> HTTP request -> FastAPI demo service -> JSON / HTTP response -> assertions -> test result / HTML report.

## 3. Requirements

- Python 3.10 or newer
- Internet access for installing packages (not needed after packages are installed)
- Postman (optional, for manual testing)
- VS Code (recommended)

## 4. Setup

Open a terminal in the project root.

### Windows

```bash
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## 5. Start the demo API

Keep this terminal open:

```bash
python -m uvicorn app.main:app --reload
```

Expected local address: `http://127.0.0.1:8000`

Open API documentation in a browser:
- Swagger UI: http://127.0.0.1:8000/docs
- Health endpoint: http://127.0.0.1:8000/health

## 6. Run automated tests

Open a second terminal in the project root, activate the same virtual environment, then run:

```bash
pytest -v
```

Generate an HTML report:

```bash
pytest -v --html=reports/api_test_report.html --self-contained-html
```

Create the `reports` directory first if it does not exist:

```bash
mkdir reports
```

The report shows actual test outcomes. A test result is not a product quality guarantee; it only describes the scenarios executed.

## 7. Run against another test environment

Set `API_BASE_URL` to the base URL of an environment you are authorized to test.

Windows PowerShell:
```powershell
$env:API_BASE_URL = "http://127.0.0.1:8000"
pytest -v
```

macOS / Linux:
```bash
export API_BASE_URL="http://127.0.0.1:8000"
pytest -v
```

Only test systems for which you have permission. Do not run tests against public or production systems without explicit authorization.

## 8. Postman setup

1. Start the local API server.
2. Open Postman.
3. Select **Import**.
4. Import `postman/QA_Practice_API.postman_collection.json`.
5. Import `postman/QA_Practice_API.postman_environment.json`.
6. Select the `QA Practice API - Local` environment.
7. Run requests in the collection from top to bottom.

The collection saves the created user ID and login token into environment variables. Some requests depend on earlier requests, so run in order. If you rerun the collection and the fixed Postman example email already exists, change the email in the Create user request before running again.

## 11. Important limitations

- Data is held in memory and resets when the API process restarts.
- This is not connected to a real shopping, banking or customer system.
- Authentication is a simplified demo implementation.
- No load, performance, penetration or security certification is claimed.
- The HTML report must be generated by running the tests; no fabricated report is included.
